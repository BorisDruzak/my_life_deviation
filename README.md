# NPC World · WORLD-0.5.1-t1

## Текущий этап автономности: T1 выполнен

Поверх исправлений T0 добавлены ограниченная `World::view_delta`, immutable LocalView,
трёхзначные временные знания, собственные известные обязательства и сериализация ControllerMemory.
158 C++-тестов и CTest 3/3 прошли на GCC Release и Clang Debug ASan/UBSan.
Физика, коэффициенты и WORLD snapshot не менялись; публичный API расширен совместимо.
Новая выполняемая policy, генератор целей, планировщик и инициатива ещё не подключены.

Начать с [результата T1](START_HERE_T1.md), [состояния этапов](docs/implementation/STATUS.md)
и [фактической проверки](reports/implementation/T1/VERIFICATION.md).
Отчёты `reports/audit_2026-09-10/` и `reports/implementation/T0/` — исторические срезы.

Автономное **C++20-ядро мира без графики и без Unreal/LLM**, подготовленное по WORLD-0.4 с исправлением неоднозначностей спецификации. Это исходный код исполняемой симуляции, а не очередной макет архитектуры.

## Статус GitHub

Рабочая ветка проекта — `main`. Поставка 0.5.1-t1 опубликована прямым Git data commit без старой схемы `.b64 → GitHub Actions → restore → push`. Служебные ветки `import/world-0.5` и `release/world-0.5.1-t1` являются историей неудачного импорта и не являются источником истины.

## Репозиторная поставка 0.5.1-t1

`main` содержит исполняемый код T0+T1, тесты, спецификации, дизайн автономности, ключевые отчёты проверки и исходную пользовательскую схему `docs/concept/original_simulation.drawio`. Повторяющиеся машинные state/event/log dumps не хранятся в Git: они воспроизводятся тестами и остаются в исходном проверенном T1 delivery ZIP. Upstream-заголовки Boost также не дублируются в Git; см. `THIRD_PARTY.md`.

Творческие области, которые ещё требуется определить до подключения полноценного генератора целей и поведения, собраны в `docs/design/CREATIVE_DECISIONS_T1_RU.md`.

## Что именно поставляется

- Библиотека `npc_world`: единый минутный исполнитель мира, потребности, предметы, деньги, договоры, наблюдения, сообщения, отношения, снимки и инварианты.
- Консольный инструмент `world_sim`: сценарные и автономные прогоны, проверка начального мира, сохранение/продолжение, журнал и проекция конкретного NPC.
- **Ограниченная экспериментальная политика**, которая живёт на локальных сведениях, выбирает покупку/просьбу/уточнение, отвечает на предложения, ест, спит, работает и отдыхает. Это НЕ свободный HTN/GOAP и НЕ универсальный социальный интеллект.
- Проверки на C++, сквозная проверка CLI, готовые сценарии, действующая документация и журнал исправлений.

Общий закон один для всех. Метка «игрок», «главный герой» или «подозреваемый» не даёт особых физических возможностей или доступа к чужой памяти.

## Быстрый запуск: Linux

Нужны компилятор C++20 и CMake ≥ 3.20. Если в системе установлен Boost >= 1.83.0, сборка использует его локально. Если подходящего Boost нет, CMake скачивает официальный архив Boost 1.83.0 и проверяет его SHA-256; это единственный сетевой шаг чистой сборки. Python нужен только для дополнительного теста CLI и вспомогательных инструментов; библиотека и executable от него не зависят.

Из корня распакованного проекта:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j 4
ctest --test-dir build --output-on-failure

./build/world_sim validate --scenario examples/household.json
./build/world_sim run --scenario examples/acquire_refuse.json --minutes 90 --out out/refuse
./build/world_sim run --scenario examples/household.json --minutes 1440 --out out/day
```

В каталоге результата нельзя случайно перезаписать предыдущий прогон: по умолчанию непустой каталог отвергается. Для сознательного повторения укажите другой путь или `--overwrite`.

### Windows

Подготовлена конфигурация для Visual Studio 2022 с инструментами C++, однако **Windows-сборка в этой поставке не проверялась**. Команды из Developer PowerShell:

```powershell
cmake -S . -B build
cmake --build build --config Release --parallel 4
ctest --test-dir build -C Release --output-on-failure
.\build\Release\world_sim.exe run --scenario examples/acquire_accept.json --minutes 90 --out out\accept
```

Запускайте команды из корня проекта либо передавайте `--data` с путём к каталогу коэффициентов.

## Что смотреть в демонстрациях

| Файл | Опыт |
|---|---|
| `examples/food.json` | Прерванная порция: 7 минут еды, отмена и продолжение остатка |
| `examples/protocol.json` | Предложение, самостоятельный ответ, текущая готовность обоих, отзыв участия и постоянная работа |
| `examples/acquire_accept.json` | Проситель считает заём разумным; второй автономный NPC соглашается |
| `examples/acquire_refuse.json` | Те же сведения просителя, но другое доверие адресата: самостоятельный отказ и переход к покупке |
| `examples/household.json` | Шесть NPC: питание, сон, работа, деньги, ограниченный ассортимент и обычные занятия |

Первые два сценария используют явные команды для проверки контрактов. Два опыта с получением инструмента и бытовой сценарий используют локальные контроллеры. Нельзя выдавать заранее заданную команду сценария за самостоятельно придуманный план.

## Файлы результата

- `events.jsonl` — **полный отладочный журнал**. В нём есть недоступная персонажам информация; нельзя показывать его игроку как дневник расследования.
- `decisions.jsonl` — локальные цели, варианты, оценки и основания выбора экспериментального контроллера.
- `samples.csv` — показатели каждого персонажа по игровым часам.
- `state.json` — полный снимок, конфигурационный и контрольный хеши.
- `initial_state.json` — исходный снимок конкретного запуска.
- `views/<actor>.json` — доступная самому NPC проекция: собственные шкалы, память, уже прочитанные сообщения, доступный инвентарь. Это не интерфейс для чтения чужих скрытых черт игроком.
- `summary.json` — счётчики, проверка инвариантов и измеренное время.

Получить локальную проекцию отдельно:

```bash
./build/world_sim view --snapshot out/day/state.json --actor n0
```

Продолжить с тем же сценарием контроллеров и тем же каталогом правил:

```bash
./build/world_sim resume --snapshot out/day/state.json \
  --scenario examples/household.json --minutes 1440 --out out/day2
```

`--scenario` при `resume` задаёт роли контроллеров и будущие скриптовые команды; физическое состояние берётся из снимка. Без него мир продолжит течь, но новые автономные команды автоматически не появятся.

Опции: `--controllers on|off`, `--check-every 60`, `--checkpoint-every 120`, `--overwrite`. По умолчанию все инварианты проверяются в начале, в конце и каждые 60 игровых минут; `--check-every 1` проверяет каждую границу, но дороже.

## С чего читать код

1. `include/npc/model.hpp` — типизированные данные, без логики.
2. `src/world.cpp` — порядок одного шага и цикл действия.
3. `src/dynamics.cpp`, `src/physical.cpp` — реальные поминутные изменения.
4. `src/action_start.cpp`, `src/action_commit.cpp` — контракт/резервы и завершение.
5. `src/social.cpp`, `src/knowledge.cpp` — независимые согласия и граница знания.
6. `src/controller.cpp` — сменяемая ограниченная политика; не читает `State`.
7. `src/persistence.cpp`, `src/validation.cpp` — сохранение и инварианты.

Ключевые границы: **владение ≠ держатель; предложение ≠ согласие; подпись ≠ готовность сейчас; доставка ≠ прочтение; событие ≠ наблюдение; факт речи ≠ истина сказанного; прогноз ≠ исполнение.**
