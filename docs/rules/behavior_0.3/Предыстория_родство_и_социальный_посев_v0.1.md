# Предыстория, родство и социальный посев

**Версия:** 0.1.0. **ID:** БИО-0.1. **Дата:** 2026-09-11. Дополнение [BEHAVIOR-0.3](Редакция_поведения_v0.3.md). Правила посева нормативные для профиля; численные настройки тестовые.

## 1. Цель и четыре разных набора данных

Генератор создаёт согласованное исходное состояние, а не проигрывает всю человеческую жизнь. Разделены: факты семейной/социальной истории мира; то, что конкретный НПС воспринимал или узнал; начальные характеристики и усвоенные предположения; результаты применения эпизодов к Q/C/W и отношениям.

«Родственник», «сожитель», «партнёр», «знакомый» и «друг» не синонимы. Фактическое родство не гарантирует личное знакомство или симпатию. Знакомство не гарантирует знания биографии. Социальная связь А→Б может отличаться от Б→А.

## 2. Детерминированный seed

Входы: беззнаковый 64-битный seed, версия генератора, хеш семантического каталога, параметры населения, логическое начало игры. Системное время, адреса памяти, hash-map iteration order и стандартный `std::hash` не используются для воспроизводимого выбора.

Ключ отдельной выборки — JSON-массив строк UTF-8 без пробелов: `[seed_hex16, generator_version, catalog_sha256, stage, entity_id, draw_index, retry_index]`. Идентификаторы и индексы представлены десятичными строками, seed — 16 строчных hex-символов. Строки нормализованы NFC. SHA-256 ключа задаёт поток; первые 8 байт трактуются как uint64 big-endian. Для равномерного целого [0,m) применяется rejection sampling: отклонить x≥floor(2^64/m)·m, увеличить retry_index и повторить; draw_index остаётся номером логической выборки. Начальный retry_index=0. Отказ одной выборки не расходует ключ следующей. Для каждого назначения отдельный stage. Порядок сущностей фиксирован по ID.

Используются отдельные стадии: родословная, домохозяйства, работа, группы, знакомства, события, личные проекции, начальные характеристики. Косметические имена вынесены из семантического хеша и отдельного потока: перевод имени не меняет знакомства. После загрузки используется сохранённое состояние, а не повторный посев.

Гарантия относится к одинаковым версиям, конфигурации и канонической сериализации. Для межплатформенной идентичности посева вероятности выбора задаются целыми весами, не плавающими распределениями стандартной библиотеки. Времена — целые миллисекунды, возраст проверяется по датам.

## 3. Родословная и домохозяйства

Первый профиль содержит только активных взрослых 18–80 лет. Для истории разрешены неактивные взрослые родственники с датами рождения/смерти/отъезда. Они не имеют тактов поведения и не входят в N активных жителей.

`ЧеловекИстории`: ID, рождение, необязательные смерть/отъезд, биологические родители, социальные родители/опекуны отдельными связями. `РольСвязи`: тип, участники, начало, окончание, источник. Для одной пары могут существовать разные роли с разными сроками.

Инварианты: человек не собственный предок; граф биологического родства ацикличен; не более двух биологических родителей; родитель родился раньше ребёнка. Возраст родителя при рождении 18–50 лет в этом тестовом генераторе — ограничение контента, не граница биологической возможности. Умерший не участвует в более позднем физическом событии; запись воспоминания о нём допустима. Жизненные интервалы каждого события проверяются.

Партнёрские пары стандартного профиля не создаются между предками/потомками, братьями/сёстрами или людьми с общим предком в пределах двух поколений. Это фильтр начального контента, не всеведущий запрет движка. Семья не обязана жить вместе. Взрослый житель с внешними родственниками допустим, но не получает ноль бытовых знакомств.

Порядок построения: создать возрастные когорты → распределить семейные шаблоны с проверкой дат → построить родословную от старших к младшим → добавить отсутствующих внешних родителей → назначить совместное проживание и партнёрские роли → валидировать DAG и временные ограничения. Невыполнимый шаблон заменяется только на другой допустимый шаблон из того же seed-потока; после лимита попыток генерация завершается ошибкой, а не противоречивым миром.

## 4. Нормальный социальный граф

Стандартная конфигурация имеет N=128. Для произвольного N≥8: каждый активный НПС имеет минимум 3 распознаваемых активных знакомых; максимум `min(32,N−2)`. Ориентир при N=128 — средняя степень 8–16, не одинаковая степень всех вершин. Плотность направленных знакомств `E/[N(N−1)]` не выше 0,25 для N≥64. Внешние родственники не засчитываются в минимальные 3 знакомства внутри поселения.

Не менее 25% и не более 65% активных НПС в стандартном посеве имеют хотя бы одного известного активного родственника; остальные могут иметь внешнюю семью. Это контролируемый диапазон тестового разнообразия, не демографическая оценка. Семьи не объединяются в один гигантский клан ради выполнения числа.

Рабочие группы, домохозяйства, соседство и занятия формируют локальные кандидаты. Общая принадлежность к большой организации не создаёт полного графа. Для межгрупповых связей используются совместное обучение, посещение общего места, знакомство через знакомого и общий проект. У каждого нового ребра есть событие контакта/узнавания, совместимое с местом и временем. Само включение ребра в технический граф не даёт знания о скрытых чертах Б.

Шаги генератора: задать роли/группы → создать обязательные допустимые контакты → дополнить до индивидуальных целевых степеней → соединить компоненты через совместимые события → проверить реальные направленные проекции и исправить недостатки. Для стандартного профиля неориентированная проекция распознаваемых знакомств связна. Это не требование, чтобы каждый знал путь ко всем другим.

При дополнении выбираются до 64 кандидатов из индексов локальных групп и адресно выбранной другой компоненты, без попарного перебора населения. Сортировка по роли/весу/ID стабильна. Максимум 16 полных попыток с ключом номера попытки. Если ограничения несовместимы, выдаётся ошибка с seed и нарушенными условиями. Запрещено молча разрешать самосвязи, знакомства со всеми или 0 знакомств. Изолированный отшельник допускается только явно именованным нестандартным сценарием.

## 5. Согласованная предыстория

После структуры создаются 8–20 значимых корневых эпизодов на НПС: знакомство, сотрудничество, помощь, успешное/нарушенное обещание, конфликт границ, приятное совместное занятие, полученное правило, наблюдаемый специфический стимул. Общий эпизод принадлежит нескольким участникам, но имеет один ID мира. Персональные проекции имеют собственные ID и маски наблюдения.

Планировщик истории резервирует интервалы участников и длительность переходов; один человек не работает в двух местах одновременно. Вещи, деньги и обещания не берутся из воздуха. Для каждого эпизода существуют начальные условия, доступные сведения, физический результат или явная пометка «сообщение о событии», а не само событие. Встречи до знакомства могут породить локальный образ, но не мгновенное правильное узнавание.

Стандартный посев задаёт разнообразие контекстов, а не обязательное приобретение каждой склонности. Специфическая реакция обучается только когда в истории присутствует наблюдаемый результат нужного канала. Приятный разговор сам по себе не создаёт сексуальную ассоциацию.

Небольшое число эпизодов не считается полной жизнью. Устойчивые исходные связи могут иметь явно заданные ранние предположения/характеристики с источником «стартовый семейный контекст». Сильная любовь не выводится автоматически из двадцати нейтральных встреч. Нельзя одновременно загрузить уже обученные W и ещё раз проиграть породившие их эпизоды.

Для каждого компонента начального состояния выбирается один режим: (а) исходное значение плюс однократный хронологический replay событий; (б) готовый снимок с уже обработанными ID. В обоих режимах происхождение хранится. Агрегированная история допустима только если эквивалентность конкретных обновлений доказана; умножение одного эпизода на «100 лет опыта» запрещено.

## 6. Минимальное содержание знаний

Каждый НПС стандартного профиля получает известные способы пить, есть, отдыхать, спать, перемещаться по знакомой части карты, искать известное место и обращаться с простым запросом. Известны собственное жильё, хотя бы один доступный источник воды/еды и одно средство обычного досуга. Знание не гарантирует текущего остатка еды, согласия адресата или отсутствия препятствия.

Роли дают усвоенное содержание конкретных правил и процедур, а не только число интеллекта. Профиль знаний не копирует весь каталог. История создаёт как общие бытовые ожидания, так и тематическое доверие и возможные заблуждения. Каждое исходное утверждение имеет источник: обучение, восприятие, сообщение, предположение или настройка. Неизвестные поля остаются неизвестными.

Короткий предварительный прогон после посева разрешён как отдельный этап. Его версия, длительность, внешние входы и финальный хеш входят в манифест. Пока ядро не реализовано, генерация предыстории не называется таким прогоном.

## 7. Приёмка будущего генератора

| ID | Проверка |
|---|---|
| БИО-01 | Повтор seed+версий даёт одинаковую каноническую историю и стартовое состояние |
| БИО-02 | Перестановка обхода контейнеров/числа потоков не меняет результат |
| БИО-03 | Перевод косметических имён не меняет смысловые связи |
| БИО-04 | Нет самородства, циклов и невозможного порядка дат |
| БИО-05 | Нет действия после смерти или одновременного присутствия в несовместимых местах |
| БИО-06 | Для 100 seed стандартного профиля нет 0 знакомств и полного знакомства со всеми |
| БИО-07 | Выполнены диапазоны степеней, плотности, известных родственников и связность |
| БИО-08 | У каждого сильного исходного эффекта есть помеченное происхождение |
| БИО-09 | Общий эпизод не обучает дважды; снимок не получает повторный replay |
| БИО-10 | Разные личные проекции общего события не принудительно одинаковы |
| БИО-11 | Невозможная конфигурация завершается диагностикой в пределах 16 попыток |
| БИО-12 | Все бытовые потребности имеют известные способы; скрытые ресурсы не раскрыты |

Измеряются число рёбер, размер истории, время посева и пиковая память отдельно. Цель реализации — работа с разреженными рёбрами и событиями, а не N²-матрица. Эти требования не являются уже выполненным нагрузочным тестом.
