# Поправки когнитивной редакции 0.4

Дата 2026-09-11. ID COG-0.4. Это дополнение к BEHAVIOR-0.3; номер не означает выпуск новой полной игры. Опорный main `fa3aec539055cafdf520d558b0e97537dcf9435b`.

Нормативные новые документы: [когнитивный контур](Когнитивный_контур_v0.4.md), [планировщик CPU](../Оптимизация/Планировщик_когнитивных_задач_v0.4.md).

## 2. Сохранение и миграция

Новая когнитивная часть состояния имеет версию `cognition-state-0.4.0`; это не автоматическая смена версии старого бинарного файла. В неё входят:

- личные оценки и альтернативные основания с Unknown/Conflicting;
- активные кандидаты, focus_since/rebuild_until, текущие роли слотов;
- episode_id, остаток бюджета, вид/прогресс операции, собственные версии посылок;
- подтверждённые и воображаемые записи с источниками/масками;
- субъективные проекты и условия возобновления;
- логические due, очередь результатов до commit, обработанные ключи событий;
- seed, версии каталогов, функции ценности, нормы/смыслы групп и политика горизонта.

Физическая CPU-задача не сериализуется как системный поток. Сохраняется её неизменяемый вход, логический прогресс и идентификатор; после загрузки pure-расчёт можно повторить без новой игровой работы/опыта. Готовность CPU — производное состояние, а уже совершённый логический commit — нормативное.

Для старого мира без такого контекста допускается только явно отмеченный переход на согласованной границе: прежние убеждения сохраняются как прежние убеждения; неподдерживаемые незавершённые мысли требуют отказа загрузки либо утверждённой процедуры завершения/отмены. Нельзя создавать фиктивную предысторию, чтобы заполнить пропущенные операции, или размножать старое Q на все контексты.

## 3. Путь интеграции с выданным C++0.7

Проверенные имена файлов архива: `include/life/mind.hpp`, `include/life/numeric.hpp`, `include/life/world.hpp`; `src/life/mind.cpp`, `src/life/numeric.cpp`, `src/life/world.cpp`, `src/life/executor.cpp`, `src/life/persistence.cpp`.

1. Сначала добавить типы PersonalBelief/OutcomeLedger и тесты отсутствия hidden-world доступа; сохранить старые Q/C/W как источники, не общие ответы по истине.
2. Заменить массовую мгновенную переоценку последовательными Op с игровым временем и общим контекстом; перестройка/приостановка имеет явные состояния.
3. Разделить длительное намерение, текущий шаг исполнителя и проект; добавить отложенные/условные результаты, не начислять ресурсы при прогнозе.
4. Соединить доступный ответ/отказ с опытом и адресными ожиданиями. Отдельно подключить порождение причинных вопросов и обновления отношений.
5. После однопоточного эталона реализовать pure-job/commit очередь и сравнить всю причинную историю. Полная параллелизация до такого сравнения не объявляется точной.

Настоящий комплект не применяет эти изменения к исходникам движка, не исправляет их по умолчанию и не объявляет завершение пунктов 1–5. Приложенный patch добавляет спецификации/эталоны и ссылку в индексе механик.
