## Фактическая поставка

T0 исправил `src/controller.cpp`; в T1 этот файл не менялся. T1 добавляет отдельный C++ API:
`World::view_delta` → `policy::apply_delta` → immutable `LocalView`, локальные запросы,
известные обязательства и `ControllerMemory::snapshot/restore`.
Старые `World::view`, WORLD snapshot, app scheduler и экспериментальные контроллеры работают по-прежнему.
Физика, коэффициенты и версия WORLD-0.5.0 не менялись. Публичный API расширен совместимо, а не оставлен неизменным.

Проверено: 158 C++-кейсов (122 T0 + 36 T1), CTest 3/3 на GCC Release и Clang Debug с ASan/UBSan.
Пять сценариев autonomy_t0 также входят в эти прогоны. Отдельно скомпилирован и выполнен пример только публичного API.

## Что не следует приписывать T1

Goal/Plan здесь сериализуемые типы, а не генератор/планировщик. Новая память не подключена как
новый режим `world_sim`. `OwnState` — явно ограниченный снимок тела/собственного счёта/когнитивных
лимитов, не замена всех полей старого ActorView. Текущий инвентарь, локальные карты отношений,
реестр известных методов и источники будущих ресурсов потребуют явных bounded-проекций при
подключении методов T3–T5; запрещено заменять их чтением глобального State.

Все слоты GC-11 сохраняются, но единый checkpoint World + scheduler + policy относится к T8.
G09/G12/P03/P13 покрыты на границе компонентов T1; полная приёмка новых scores/trace/command
и ResolveUncertainty остаётся на этапах соответствующих генераторов. Подробная карта —
`reports/implementation/T1/acceptance_mapping.json`. Исходные 61 design-case не объявлены пройденными.

Начать с R01–R05: точное разложение drift/effect/clamp, полуоткрытые окна наблюдения,
цензурированные эпизоды, выключенная N05 и повторный финальный sample. После RED добавить
потоковые агрегаты и версионированную трассу фактического выбора, включая отсутствие команды.
Не переставлять физические суммирования и не включать T3–T9 в этот этап. Повторить все 158
C++-кейсов, прежний CLI и autonomy_t0. Репозиторная поставка 0.5.1-t1 опубликована в `main`; служебные import/recovery workflow больше не являются частью рабочего контура загрузки.
