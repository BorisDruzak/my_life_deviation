# Действующие контракты A01–A32

Контракты исполняются одинаково для NPC, команды теста и будущего игрока. Для каждого обычного действия нужны alive/capable, свободный слот, корректные параметры и необходимые знания/доступы. Финальные условия перепроверяются. Неизвестный параметр не игнорируется.

Стоимость времени возникает из реально прошедшей длительности; деньги/материалы меняются по контракту. Порог допустимости и моральная цена принадлежат выбору способа контроллером, а не физическому запрету мира на одинаковое действие.

## A01 · Ждать

**Параметры:** `minutes=1..120`.
**Длительность:** 1..120.

Собственное разрешённое место; ничего кроме фоновой динамики.

При отклонении до старта ресурсы не расходуются. После добровольного прерывания уже прошедшие непрерывные эффекты остаются; ещё не совершённая дискретная передача не появляется. Для A22 применяется отдельная control-фаза.

## Рецепты

Семантика рецептов фиксирована реализацией R01–R03, свойства проверяются против конкретных предметов. Новый рецепт требует исполняемого контракта и теста; добавление произвольного JSON effect не запускает код.

R01: ингредиенты I04, кухня F02, 20 минут → один обед I01. R02: объект F03, инструмент I05, комплект I06, навык repair≥0.5, 30 минут → condition=1. R03: груз F05, верёвка длиной≥3м/условной прочностью≥20, 10 минут → та же верёвка installed, груз secured.

Для всех трёх при pause/resume сохраняются creator/place/inputs/tools/worked/required. Нет нового продукта при каждом запуске команды возобновления.

## События и метаданные

`catalog.events` содержит действительные имена, общий shape публикуется типом Event. Локальная projection может иметь другое имя/меньший набор полей (например, нераскрытая неразрешённость передачи). Конфигурационный каталог не выдаёт событие сам: оно создаётся конкретным обработчиком.
