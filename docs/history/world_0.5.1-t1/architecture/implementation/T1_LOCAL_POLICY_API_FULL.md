# T1: контракт локальной проекции, знаний и памяти

**Реализовано:** POLICY-0.1, `ACTOR-VIEW-1`, `POLICY-STATE-1`, `LOCAL-KNOWLEDGE-1`.
**Мир:** WORLD-0.5.0; новая схема policy не меняет физическую схему мира.

## 1. Границы и ответственность

`World::view_delta(actor, cursor, limit, receipt_ids)` — транспортный адаптер доверенного
исполнителя. Только этот адаптер читает State. `apply_delta(memory, delta)` проверяет и
индексирует доступные NPC записи, затем выдаёт immutable LocalView. Policy-модули не получают
World/State и не вызывают старый всеведущий debug API.

LocalView нельзя создать пустым или сконструировать из World/State. Доступные поля возвращаются
по const-ссылке/указателю. Неизменяемые AVL-индексы используют структурное разделение данных:
новая порция не переписывает старый view, а ветвление ControllerMemory не изменяет оригинал.
Указатели из view действуют, пока живёт соответствующий view. Это архитектурная граница
локальных данных, не песочница против злонамеренного C++ кода в том же процессе.

Транспорт не вызывает `World::view` и не кодирует весь Actor перед обрезанием результата.
Старый полный `World::view` сохранён для legacy-контроллеров и явного экспорта.
`LocalView::export_json` и `ControllerMemory::snapshot` — намеренно полные, дорогие операции;
их нельзя помещать в обязательную подготовку каждой bounded-попытки планирования.

## 2. Полезная нагрузка и бюджеты

| Часть | Что поступает | Ограничение |
|---|---|---|
| OwnState | Свои зарегистрированные N01–N05, деньги, положение, здоровье/нагрузка, способность, active_action, horizon/search_width | Фиксированный набор скаляров и зарегистрированных потребностей |
| Evidence | Ранее доступные и вновь полученные собственные belief-записи, без изменения исходной истории | Вместе с конвертами не более 64 на один вызов |
| LocalEnvelope | ID, отправитель, канал, время доставки, собственная отметка прочтения | Тот же общий лимит; тело никогда не входит в конверт |
| LocalReceipt | Только явно запрошенные собственные команды, публичный статус/reason, request и время наблюдения | Не более 4 ID отдельно от бюджета истории |

`limit` допустим в [1,64]. История свидетельств и история конвертов чередуются при одновременном
наличии записей: большой архив свидетельств не блокирует первую информацию о непрочитанных письмах.
Курсор хранит две позиции, два хеша префикса и очередность потоков. `records_examined` равен
числу реально взятых evidence + envelope, а не размеру результата после полного сканирования.
`has_more` честно сообщает незавершённое чтение. Продвижение по курсору не зависит от скрытого
тела письма. Изменение собственного read-флага не ломает хеш доставки.

Проекция разрешена только на ready-границе World. Курсор другого actor, неправильный префикс,
выход за конец, budget=0/65 и повторные ID в receipt watch возвращают InputError.
Несуществующий и чужой receipt одинаково не выдаются; `debug_reason` и fingerprint исключены.

Хеши префиксов строятся один раз при конструировании/восстановлении World, затем пополняются
при добавлении знания/доставке. Они — производный кеш вне State; поэтому не меняют WORLD hash.
Построение индекса при restore зависит от всей накопленной истории и не заявляется bounded.

Лимит — число записей, не байтов/наносекунд. Размер JSON-свидетельства и его roots пока не имеет
нового маленького hard limit; WORLD хранит историю без сборки мусора. Обновление собственного
persistent index копирует путь AVL, а не весь архив; перенос/хеширование одной записи зависит
от её размера. Это не доказательство real-time поведения на 1000 NPC.

**OwnState пока не заменяет весь ActorView.** В нём нет неограниченных карт relations/inventory,
реестра методов, программ работы и произвольных traits. Их bounded-проекции надо явно спроектировать
при интеграции T3–T5, а не подставлять скрытые свойства предметов/других людей. Новая policy
ещё не является выполняемым контроллером CLI.

## 3. Установка и чтение LocalView

```cpp
#include "npc/world.hpp"
#include "npc/policy/knowledge_query.hpp"
#include "npc/math.hpp"

// world/config уже созданы вызывающей стороной. policy_hash — SHA-256 канонической
// конфигурации подключаемой политики; не подменять его world.config().hash.
const auto policy_hash = npc::math::sha256(npc::canonical(npc::Object{
    {"version", "POLICY-0.1"}, {"purpose", "my-controller"}}));
npc::policy::ControllerMemory memory("a", config.hash, policy_hash);
auto local = npc::policy::apply_delta(
    memory, world.view_delta("a", memory.cursor(), 64, {"a@7"}));

const auto own_tick = local.own().tick;
const auto unread = local.unread_messages(8);
const auto deadlines = local.nearest_commitments(8);
```

`unread_messages` и `nearest_commitments` возвращают не более запрошенного числа из [1,64].
Чтение A24 и доступная read-evidence обновляют локальный unread-индекс. Полученный конверт
не означает прочитанное предложение, принятое обязательство или согласие участника.

После apply_delta курсор памяти уже продвинут. Повторное применение той же непустой страницы
не является повторным событием: оно отвергается. Все InputError в проверке/индексации страницы
оставляют прежнее знание и курсор без частичных вставок. Нулевая новая история допустима;
на следующей минуте можно обновить тело и собственные receipts без повторного чтения архива.

## 4. Трёхзначный запрос и время

`query_belief(LocalView, BeliefQuery, optional PersistenceRule, evidence_limit)` ищет точную
тройку `(subject, predicate, canonical arguments)`. Полярность запрашивается отдельно.
Это не универсальный логический язык и не семантический поиск.

`BeliefResult` содержит `KnownTrue / KnownFalse / Unknown`, confidence, reason, complete,
examined и ссылки на фактические sources с корнями, effective confidence, observed_at,
applies_at и assumed. Ни одна запись не меняет исходное Statement.

Текущие правила POLICY-0.1:

- Нет источника — Unknown с confidence 0.5, а не KnownFalse.
- Полярность с confidence ≥0.75 при отсутствии поддержки противоположной стороны >0.5
  даёт KnownTrue либо KnownFalse. Это фиксированный инженерный порог T1, не эмпирический
  психологический норматив. Confidence в результате относится к истинности запрошенной полярности.
- Есть поддержка обеих полярностей >0.5 — Unknown/conflicting_sources. Порядок записи не
  выбирает удобную истину. Совпадающие/коррелированные источники не складывают уверенность:
  используется максимальная поддержка, а не сумма независимых свидетельств без оснований.
- Просмотр ограничен 64 источниками точного ключа. Если bucket больше лимита либо осталось
  необработанное локальное поступление, complete=false и Unknown/query_budget_exhausted
  либо Unknown/unprocessed_local_history. Обнаруженный фрагмент не выдаётся за полный ответ.
- Интервалы свидетельств включают обе границы. `valid_until=-1` — единственный сохранённый
  legacy-сентинел открытого интервала; он не является разрешением отрицательных policy ticks.
- Запрос допускает время [0, own.tick]. Это «что известно сейчас об указанном времени»,
  не реконструкция того, что NPC знал в прошлом: сведения, изученные позднее события, можно
  использовать для исторического вопроса.

Legacy `item_seen`, `shop_stock`, `person_seen` интерпретируются как наблюдение в момент
`valid_from`, даже если исходный WORLD записал `valid_until=-1`. На другой момент это не
доказательство текущей доступности. Первоначальная запись остаётся побитово прежней.

Продление допустимо только при явно переданном `PersistenceRule` для того же predicate,
положительном конечном half-life и нейтральном prior=0.5:

`confidence(t) = 0.5 + (confidence_observed - 0.5) * 2^(-(t-observed_until)/half_life)`.

Продлевается observation, а не произвольная чужая claim. Отсчёт идёт от времени наблюдения,
не от позднего поступления в память. В источнике стоят assumed=true и оба времени;
итоговая reason показывает persistence_assumption. Без правила продления — Unknown/expired_evidence.
Отдельные зарегистрированные hypothesis используют собственный half_life; общий вывод гипотез T1 не создаёт.

## 5. Известные обязательства

Извлечение принимает собственные доступные `proposal/proposal_update` с полным набором подписей
участников, accepted-state и confidence=1. Результат содержит proposal/version, должника и
кредитора, вид, terms, срок, сумму/известный остаток, status, source_refs и resolved_at.
Нет чтения `State.obligations` или отношений другого actor.

Поддержаны подписанный repair, условный loan_item/loan_money, локальное участие joint/private,
доступное изменение срока при известных исходных условиях. Loan agreement — ещё не возникший
долг: до подтверждённой передачи status=agreed, remaining отсутствует. Собственный успешный
A13 или доступная запись obligation_created подтверждает возникновение долга.

Собственная частичная выплата уменьшает известный остаток однократно. Повторный просмотр того
же receipt не является ещё одной выплатой. Ключ учитывает команду, режим, обязательство,
самого отправителя, получателя и предмет. Исполнение/возврат известны только после доступного
подтверждения; одно изменение глобального status другого NPC не меняет локальный вывод.
Пропуск срока не создаёт скрытую телепатическую информацию об исполнении/нарушении.

Собственные завершённая/прерванная A15/A32 терминальны для конкретных proposal+version.
Из нескольких локальных терминальных подтверждений сохраняется первое наблюдённое
(при равенстве — стабильный ID); restore не меняет его из-за сортировки записей.
`observed_at` — момент доступного наблюдения квитанции, не заявка на точное скрытое время исхода.
Rejected сам по себе не завершает участие. Терминальные обязательства исключаются из ближайших сроков.

Конфликтующие подписанные terms одной версии дают unknown. Неподписанные, чужие и повреждённые
protocol-looking claims не становятся обязанностью. Исходная ошибочная claim остаётся в памяти;
она не приводит к выдуманному долгу или падению от произвольного содержимого сообщения.

## 6. Память GC-11 и сериализация

Сохраняются все поля GC-11: версия/хеш политики/actor; decision_sequence; счётчики episode;
Goal; active Plan и cursor; session_runtimes; calendar_intents; cooldowns; outcome_history;
knowledge_cursor; known_query_index; next_regular_review_tick; fair_scan_cursor;
pending_command_links; pending_notifications. Дополнительно фиксируются world_config_hash,
последнее OwnState, конверты, собственные receipts и известные обязательства.

```cpp
const npc::Json saved = memory.snapshot();
npc::write_json("out/policy-a.json", saved);
auto restored = npc::policy::ControllerMemory::restore(
    npc::read_json("out/policy-a.json"), config.hash, policy_hash);
```

Format=`npc-policy-memory`; версия файла `POLICY-STATE-1`; policy_version=`POLICY-0.1`.
`state_hash` вычисляется по каноническому payload. При restore обязательны совпадающие внешние
world/policy hash. Пустые slots также записываются: тихое восстановление пропущенных полей
через C++ defaults не допускается. Производные индексы перестраиваются из сохранённых
локальных источников и сверяются с записанными commitments и receipt index.

Проверяются закрытые enum-статусы, отрицательные/предельные ticks, конечность чисел,
дубликаты goal ID и канонических ключей, соответствие family/target, версия session/proposal,
родительские ссылки и циклы, ссылки Plan/calendar/pending, размер плана ≤12, собственность
actor/command, курсор и хеши. Изменять actor/config существующей памяти нельзя — нужен новый
экземпляр либо будущая явная миграция. Повреждение выдаёт InputError, не частичный успех.

`edit_state()` предназначен будущему генератору/монитору; он не реализует переходы статусов.
Граница snapshot валидирует полное control-состояние, apply_delta — поступившие данные и идентичность
памяти. Вызывающая политика отвечает за корректные переходы между своими изменениями.
SHA-256 — контроль целостности, не криптографическая аутентификация недоверенного сценария.

## 7. Совместимость и честная граница приёмки

WORLD snapshot не расширен policy-полями. Пример в
`reports/implementation/T1/public_api_smoke.cpp` отдельно сохраняет и восстанавливает World
и ControllerMemory на одной границе и проверяет равенство после дальнейших двух минут.
Это не атомарный checkpoint всего приложения. Scheduler sequence, общий runner и восстановление
новой выполняемой политики включаются в T8 после T3–T7.

G09/P03 проверены на локальных данных (для P03 также прежний `decide`), G12 — на всех полях
памяти и возобновлённой проекции, P13 — на временной Unknown-семантике. Полная будущая trace,
candidate scores, самостоятельная ResolveUncertainty и следующие команды новой политики
здесь не заявляются. Матрица проверки и фактические результаты находятся в отчёте T1.
