**Дата среза:** 10 сентября 2026 года. **Статус:** T1 реализован и проверен; T2–T9 не реализованы.
**Основа:** `NPC_World_0.5_T0_completed.zip`, SHA-256 `077fb9d6bb82f42ab00870ebd4f21bdee243a080863334461ede3ef71e5c5ef5`.
**Baseline commit:** `afe29956d602f3f9f41f8492b16454966ca1a17d` — локальный импорт предоставленного архива, не GitHub SHA.
**Локальная ветка:** `t1/local-policy-state`. GitHub не читался и не изменялся.

## Реально выполненное изменение

Добавлены транспорт `ActorViewDelta`, immutable LocalView, ControllerMemory и сериализуемые
Goal/Plan/Session/Calendar/Outcome/Pending-типы. Новые policy-функции не принимают World/State.
Две курсорные истории (свидетельства и конверты) читаются с общим пределом 64, чередуясь;
четыре явно наблюдаемых собственных receipt можно получить независимо от длинного backlog.
Скрытое тело непрочитанного письма, чужие needs/relations, глобальный obligation.status,
receipt.debug_reason и fingerprint в новую проекцию не входят.

История, точечные запросы, собственные квитанции и ближайшие обязательства индексируются
структурно разделяемым неизменяемым AVL-деревом. Обновление не копирует всё прошлое знание
ради каждого нового view. Реализация индекса проверяется против std::map на 8000 детерминированных
операций; сохранённые старые корни также сверяются.

Запрос выдаёт true/false/unknown, причины, временную применимость и доступные источники.
Конфликт полярностей не разрешается последней записью. Прежний open-ended shop_stock/item_seen
не считается текущим наличием: по умолчанию это наблюдение в определённый момент. Явное правило
persistence хранит assumed и снижает confidence от времени наблюдения, не от времени загрузки.
Превышение бюджета/неполная история дают Unknown, не придуманное доказательство недоступности.

KnownCommitment выводится из доступных подписанных terms, доступных наблюдений и собственных
успешных receipts. Согласие занять не равно получению денег; повторная квитанция не вычитает
платёж повторно; прерванная сессия терминальна для собственной proposal+version. Timestamp
сохраняет момент наблюдения, даже если страница обрабатывается позже.

Все GC-11 slots сохраняются вместе с локальным индексом; state/world/policy hashes и строгая
схема валидируются. Проверяются неизвестные статусы, отрицательные ticks, дубли ключей,
семейство/цель, ссылки/cycles/cursors, чужие actor/commands и неполные поля. Повреждённая
страница не оставляет частично вставленных записей. Идентичность существующей памяти нельзя
переписать другим actor или config hash.

## Что в существующем коде изменено

`include/npc/world.hpp` расширен новым API и производными history-кешами. `src/world.cpp`
однократно строит кеш, `src/knowledge.cpp` пополняет его при добавлении evidence/конверта.
`CMakeLists.txt` подключает новые sources/tests. Остальная runtime-реализация WORLD не менялась.

В частности, `src/controller.cpp` с T0, `app/main.cpp`, `src/persistence.cpp`, физические
исполнители и файлы data/ сохранены. Старый `World::view` не подменён, CLI по-прежнему
использует экспериментальные контроллеры. WORLD snapshot/version/hash физики не расширены.
Новых внешних runtime-зависимостей не добавлено. Список всех файлов и хешей — manifest поставки.

## Ключевые проверенные сценарии

**Нет телепатии:** два World с одинаковыми данными actor a, но разными чужими needs, тайными
relations и состоянием чужого предмета дают одинаковые новые local export/memory и legacy
решение. Даже разные тела непрочитанного доставленного письма не меняют cursor/local snapshot.

**Ограниченное чтение:** 145 evidence выдаются как 64/64/17/0. Для 130 evidence + 8 конвертов
budget=4 даёт два evidence и два envelope при наличии обоих потоков. Восстановленный World
и восстановленная policy продолжают с той же позиции и очередностью. Запрос собственных
receipts доступен при backlog из 200 evidence. Это проверки счётчиков, не benchmark 1000 NPC.

**Реальный заём:** через A11/A12 подписывается заём 20; до выдачи remaining отсутствует.
После реальной A13 передачи — 20; после погашения 7 — 13; повторное чтение receipt оставляет 13;
snapshot/restore сохраняет результат; после погашения ещё 13 — fulfilled/0, запись исчезает
из ближайших сроков. World balances после возврата: a=80, b=50. Всё исполняется настоящим World.

**Стабильность времени/версии:** поздняя обработка квитанции сохраняет её observed_at=5,
не подменяя на tick обработки 20. Квитанция другой версии не закрывает старую сессию.
Порядок хранения receipt в snapshot не меняет первое известное терминальное участие.

**Сохранение:** проверены waiting_response, cooldowns, goal IDs, episode counters, plan cursor,
calendar, outcomes, последовательность команд и все остальные slots GC-11. Payload сверяется
канонически. Будущая команда нового планировщика не генерируется этим тестом, поскольку T5
не реализован. Public API smoke отдельно проверяет равенство World и локальной памяти после
двух минут с ручным сохранением обеих частей на одной границе.

## Воспроизведение

```bash
cmake -S . -B build-t1 -DCMAKE_BUILD_TYPE=Release
cmake --build build-t1 --parallel 4
./build-t1/npc_tests
ctest --test-dir build-t1 --output-on-failure

cmake -S . -B build-t1-sanitize -DCMAKE_CXX_COMPILER=clang++ \
  -DCMAKE_BUILD_TYPE=Debug -DNPC_SANITIZERS=ON
cmake --build build-t1-sanitize --parallel 4
ctest --test-dir build-t1-sanitize --output-on-failure

c++ -std=c++20 -Wall -Wextra -Wpedantic -Werror -ffp-contract=off \
  -Iinclude -isystem third_party reports/implementation/T1/public_api_smoke.cpp \
  build-t1/libnpc_world.a -o build-t1/t1_public_api_smoke
./build-t1/t1_public_api_smoke
```

Среда зафиксирована в `environment.txt`. `git diff --check` выполнен; итоговая проверка
пакета также проверяет SHA256SUMS, CRC ZIP и применимость патча к исходному архиву T0.

## Ревью и ограничения

Проведено собственное построчное ревью diff, контрактов privacy/temporal/serialization и
проверок. Независимый subagent-review не запускался; результаты инструмента не подменялись
выдуманным ревью. Код не требует подключения сети или LLM.

T1 — завершённый фундамент данных, а не новая выполняемая политика. В OwnState входит
ограниченный снимок тела и средств, но не весь инвентарь, relations и known-method registry;
для будущих методов нужны явные bounded-проекции. Goal/Plan только хранятся/валидируются:
генерация, score, выбор команды, изменения намерений и инициатива относятся к T3–T7.

Общий checkpoint World/runner/policy и full next-command resume — T8. Полные design G09/G12/P03/P13
не объявлены пройденными; их компонентная карта в `acceptance_mapping.json`. Все 61 design-case
в `acceptance_cases.json` остаются спецификацией, не новым исполненным набором.

Лимит 64 относится к записям поступления, а не размеру всего архива, байтам или CPU.
Initial index rebuild/export/snapshot проходят накопленную историю. Windows, недельный прогон,
нагрузка 1000 NPC, интеграция UE и full автономный checkpoint в T1 не проверялись.

**Следующий этап:** T2, exact needs aggregates и фактическая decision trace. Рабочая база —
текущий T1 archive, не исходный T0 и не GitHub main.
