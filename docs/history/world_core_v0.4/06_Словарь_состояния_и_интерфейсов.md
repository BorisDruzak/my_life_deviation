# Словарь состояния и интерфейсов
## Приложение к WORLD-0.4

Документ фиксирует структуру данных, которая необходима закону F. Это контракт будущей реализации, не готовая C++-библиотека. Синонимы в русском тексте не должны превращаться в независимые дублирующиеся поля.

## 1. Общие типы

`Id` — непустая неизменяемая строка, уникальная в своём пространстве. Удалённые ID не используются повторно. `Minute` — целое ≥0. `Ratio` — конечное [0;1]. `NeedValue` — конечное [0;100]. `Money` — целое ≥0. `Version` — возрастающее целое. `StatementRef` всегда сопровождается проверкой доступности владельцу представления.

Отсутствие optional поля обозначается null или отсутствием ключа согласно схеме конкретной сущности. Null, false и числовой 0 различаются. Обязательное поле нельзя заполнять null «пока неизвестно»: неизвестность хранится внутри утверждения/предположения, а не ломает тип состояния.

## 2. Оболочка полного снимка

| Поле | Тип и правило |
|---|---|
| rules_version | Строго WORLD-0.4 |
| config_hash | SHA-256 фактически загруженных параметров и каталогов |
| profile | baseline или extended |
| time | Minute |
| phase | ready; сохранять на границе полного тика |
| seed | Неизменяемая строка |
| topology | Словарь мест и рёбер |
| actors | Словарь полных состояний акторов |
| objects | Словарь экземпляров и стационарных объектов |
| accounts | Денежные счета, включая отдельно размещённый escrow, если выбран |
| permissions | Версионные права доступа |
| reservations | Активные/будущие резервы |
| actions, jobs | Исполняемые действия и сохраняемые работы |
| proposals, obligations | Версии, подписи, объективные сроки и статусы |
| records, messages | Цифровые записи, версии, ACL и очереди доставки |
| scheduled | Отсортированная очередь внешних часов/доставок/выплат |
| ledger_cursor | Применённый префикс журнала |

Снимок одного NPC не является снимком мира. Нельзя восстановить содержимое банковского счёта или ящика только из памяти его владельца.

## 3. Состояние актора

| Раздел | Обязательные данные |
|---|---|
| identity | actor_id, дата рождения, appearance, биографические ссылки |
| immutable_traits | patience, caution, social_initiative, confrontation, novelty; все Ratio |
| physical_traits | carry_capacity_kg>0, base_speed>0, индивидуальные ограничения пищи |
| cognition_parameters | Конфигурация контроллера; мир не использует её в питательности и согласии |
| need_parameters | Для каждого включённого N: скорости, c, θ, r, enabled |
| needs | Текущие включённые значения N01–N05 |
| threshold_latches | need_active, critical и защёлки возрастающих состояний |
| physical_state | health h, fatigue F, pain, impairment, alive, capable, heavy_work_allowed |
| emotional_state | stress S, fear, selfesteem E, baseline E0, направленная anger_by_target |
| interests | topic_id → Ratio; незаданная знакомая категория нейтральна 0.5 |
| repetition | topic_id → неотрицательный след R |
| skills | skill_id → Ratio; известность метода отдельно |
| known_methods | Множество method/action/recipe identifiers |
| drives | drive_id → {enabled, intensity q, pressure D, parameters} |
| placement | At / Transit / Stranded |
| active_action | action_id либо null |
| local_beliefs | Сведения, утверждения, гипотезы, sources и confidence |
| relation_outgoing | target_id → {A,T,X, optional V, expectations} |
| protected_preferences | Вес и порог рассмотрения, но не объективная истинность условия |
| inbox | Доставленные, ещё не прочитанные сообщения |
| money_account | Ссылка на счёт, не копия баланса |
| wellbeing | EMA B и последнее время обновления |

При неизменном мире заменить только cognition_parameters нельзя трактовать как изменение физических законов. При исполнении тех же команд получаются те же изменения; различаться могут команды, выбранные контроллером.

## 4. Экземпляр объекта

`object_id`, `type_id`, `owner_id`, `placement`, `condition`, `created_by_event`, `version` обязательны. Порция дополнительно имеет total_units и remaining_units. Контейнер — capacity и is_open/lock_ref. Техническая цель — progress/condition и разрешённые рецепты. Установленный объект имеет placement=Installed(target), а не удаляется как «потраченная верёвка».

Свойства типа и экземпляра разрешаются так: immutable type defaults → явно разрешённые instance overrides → зарегистрированные dynamic fields. Нельзя менять массу ключа произвольным override, если такое поле не разрешено.

## 5. Поступающая команда

```json
{
  "actor_id": "npc_anna",
  "issuer_seq": 17,
  "kind": "action",
  "type_id": "A06",
  "bindings": {"shop_id": "shop_1", "item_id": "meal_42"},
  "expected_versions": {"meal_42": 3},
  "intent_ref": "own_intent_12",
  "signature_refs": []
}
```

Здесь intent_ref — приватная ссылка актора, а не запрос мирового знания. Мир не обязан понимать высокоуровневую мотивацию, чтобы проверить покупку. Команда использует реальные зарегистрированные ID; пример не является полным тестовым миром.

Ключ идемпотентности: `(actor_id, issuer_seq)`. Повтор с тем же содержанием возвращает старый результат/состояние команды; с другим содержанием — конфликт ID. Исполнитель не принимает произвольную коллекцию дельт от контроллера вместо зарегистрированного type_id.

Контрольная команда A22 имеет kind=control; она допускается перед одной обычной командой той же границы. Она не может зачислить ресурсы, прогресс или удовольствие. У постороннего нет права отозвать согласие другого человека.

## 6. Результат команды

`command_received` означает только принятую оболочку. После арбитража возможны `started`, `rejected`, позднее `completed` или `interrupted`. Отклонение не расходует d минут несуществующего действия, но при отсутствии нового действия фоновые процессы на текущей минуте всё равно идут.

Наружные причины ограничены доступной информацией: «нет доступа», «объект недоступен», «занято», «условия изменились». Точный hidden holder, его цель и содержимое закрытого контейнера выдаются только private debug. Нельзя превращать ошибки предусловий в универсальный инструмент чтения скрытой памяти.

## 7. Предложение и готовность к совместному действию

Подписанная договорённость содержит точные условия и версию. Текущая ready-подпись участия действительна только для заданной сессии/окна. Она не означает бессрочного согласия. Обмен предложениями не должен блокировать действия получателя до его решения.

Для физической передачи или совместного старта требуется реальное присутствие; для цифрового согласия — доступная доставка и чтение. Согласие на время 19:00 не переносится автоматически на 23:00.

## 8. Образец одного события

```json
{
  "event_uid": "npc_anna:17:purchase:0",
  "sequence": 1042,
  "occurred_at": 1323,
  "phase": "completion",
  "event_type": "purchase",
  "action_id": "npc_anna:17",
  "participants": ["npc_anna", "shop_1"],
  "objects": ["meal_42"],
  "cause_ids": ["npc_anna:17:start:0"],
  "committed_delta": {"buyer_money": -30, "seller_money": 30},
  "projection_schema": "purchase_visible_fields",
  "private_reason_ref": "own_intent_12"
}
```

Полный внутренний transaction delta включает перенос предмета и квитанцию; пример показывает только часть числовых полей. Проекция для наблюдателя не содержит private_reason_ref и не обязана содержать цену/товар, если они не были видны.

## 9. Расширение без изменения законов

Можно добавить новый тип еды с другой питательностью и ценой, новое место с графиком, персонажа с другими порогами или рецепт с другими требованиями. Это данные той же версии при сохранённой семантике.

Новый способ перенасыщения, второй параллельный слот действий, истинное свободное понимание диалога, новая причинная связь «стресс → личность», другая трактовка согласия или условие автоматического наказания — изменение правил, требующее новой версии и тестов миграции.
