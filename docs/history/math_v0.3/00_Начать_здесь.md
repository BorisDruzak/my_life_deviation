# Ядро симуляции НПС: математическая редакция 0.3

09.09.2026. Дополнение к архитектурной схеме0.2, а не готовая игра.

## Файлы

**01_Математическая_спецификация.md** — единицы, состояния, потребности, формулы, типы порогов, оценка планов, знания, совместные решения, семантические ответы и порядок времени.

**02_Каталог_действий_событий_предметов.md** — полные карточки27действий,25событий,12переносимых предметов,5стационарных объектов,3рецепта,9методов и входной сценарий6НПС.

**catalog_v0_3.json** — те же параметры и контракты в машиночитаемом виде. Это не исполняемый язык: условия/эффекты в карточках пока являются требованиями к реализации.

**check_math.py** — независимые проверки арифметики и структуры каталога. Python3.10+, только стандартная библиотека. Это вспомогательный скрипт проверки, не выбор Python для будущего ядра: решение о независимом C++-модуле сохранено.

**03_Проверка_и_границы.md**, **verification_results.json**, **verification.log** — фактические результаты запуска проверок и их ограничения.

## Проверка

Распаковать все файлы в одну папку. Из этой папки выполнить:

```sh
python check_math.py
```

Скрипт читает JSON рядом с собой и обновляет verification_results.json. Не требует Unreal, сети, библиотек или графического интерфейса.

## Что уже сделано

Формулы определены, коэффициенты назначены как стартовые, контракты описаны, примеры и связи каталога проверены. Ни одному NPC не прописан победивший план «попросить Колю».

## Что ещё не сделано

Движок не исполняет27действий: его пока нет в этом комплекте. Нет запуска симуляции суток, балансировки, нагрузки1000НПС и проверки интереса игрока.60успешных локальных проверок не заменяют эти этапы.

Архитектурная draw.io-схема не изменена: этот комплект добавляет формальные описания, не увеличивает её холст. Соответствие разделам схемы приведено в документе01.
