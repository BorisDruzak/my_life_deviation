# Каталог действий, предметов и событий — 0.3

Статус: нормативный проект малого цифрового стенда. Условия и эффекты ниже — требования к коду; JSON не содержит готового интерпретатора и не запускает симуляцию. Значения — стартовые игровые параметры.

## 4. Общий контракт действия

Условия начала проверяются по реальному миру исполнителем, условия выбора — по представлениям NPC. Неизвестное условие не равно выполненному. В прогнозе нет реального списания, передачи, события или изменения общего генератора случайности. Все длительности — целое число игровых минут, минимум 1. Для всех действий создаются служебные начало/конец или отказ; поле `events` перечисляет существенные доменные события.

Конкурирующие ресурсные заявки решаются до старта. После старта у действия есть action_instance_id, start_time, due_time, progress, versions и reservations. Уже применённые эффекты не повторяются при загрузке и не откатываются при отмене. Приготовление и ремонт возобновляют существующий job, а не начинают повторное расходование материалов.

Занятость: body — перемещение, сон, еда и предметная работа; attention — чтение и исходящая коммуникация. В 0.3 у каждого актора один выполняемый примитив: body и attention несовместимы для него. Пассивное получение сообщения не занимает action-slot и не означает ответа; совместный примитив занимает слот обоих по согласию. `channel` — доставка, а не блокировка воли адресата.

## 6. Общие методы планирования

### H01 · Обеспечить питание

Вариант 1: свой пригодный продукт → A07.
Вариант 2: свои ингредиенты + кухня → A08 → A07.
Вариант 3: H02 получить еду → A07.



### H02 · Получить предмет с требуемыми свойствами

Вариант 1: из своего доступного запаса → A04.
Вариант 2: из известного магазина → путь A02 → A06.
Вариант 3: у знакомого → A11 → внешнее решение A12 → при согласии путь и A13.

### H03 · Выполнить техническую задачу к сроку

Вариант 1: Найти известный R02/R03 с требуемым результатом → H02 получить инструмент и материал → путь → A21.

Вариант 3: A19 предупредить о невозможности; обязательство автоматически не исчезает.

Вариант 1: путь к известной доступной кровати → A09.
Вариант 2: уточнить доступ → затем A09.



### H05 · Удовлетворить общение

Вариант 1: A14 предложение → A12 → встреча → A15.
Вариант 2: иной известный партнёр с новым предложением после допустимого интервала.

Вариант 1: вернуть предмет через A11/A12/A13.

Вариант 1: A03.
Вариант 2: A17 → A18.
Вариант 3: A24.

Выбирать по ожидаемому улучшению последующего решения, не по бонусу за объём памяти.

Денежная передача использует A13 со специальным типом fungible_money: дебет/кредит и реальное обязательство. Не предмет из каталога.
