# Планировщик когнитивных задач COG-0.4

Версия 0.4.0; 2026-09-11. Основания: [когнитивная спецификация](../Механики/Когнитивный_контур_v0.4.md), SAFE-OPT-0.1, OPT-0.3. Это алгоритмический контракт точного планирования работ и отдельный C++-эталон, не доказательство ускорения полного мира.

## 1. Три очереди — три разные задачи

| Очередь | Чьё время и содержание | Что в ней находится |
|---|---|---|
| Кандидаты внимания НПС | Психологическая модель | До 32 разрешённых собственных тем; приоритет субъективный |
| Логические события | Время симуляции | Завершения действий/мыслей, восприятие, физические границы, сроки |
| Готовые работы CPU | Физическая машина | Чистые вычисления снимков; задания могут исполняться разными потоками |

Первая очередь не FIFO: низкоприоритетная мысль может так и не получить фокус. Третья должна исключать техническое голодание работ, но не обязана делать НПС психологически справедливым к собственным мыслям. Низкий номер НПС, расстояние до камеры и загруженность компьютера не изменяют его способности.

## 2. Два времени одной мысли

Операция начинается в логическом `t0`, имеет стоимость работы 1 и скорость `2+6*Speed`. При постоянной скорости ожидаемое завершение:

`due=t0+ceil(1000*(1−completed_work)/rate)`.

Вычисление на CPU может занять микросекунды или несколько физических кадров. Это **не** определяет due. Результат хранится в буфере до логического завершения. Если свой вход изменился до due, результат устаревает; если меняется скорость, очередь пересчитывает due по оставшейся работе, разрезая интервал.

Приоритет CPU отвечает за то, какие подготовительные работы выполняются раньше, а не за то, какой НПС первым получил право на ресурс. Атомарный обмен и другие конфликты по-прежнему разрешает исполнитель с устойчивым ключом события конкуренции.

## 3. Консервативная граница продвижения

Первая реализация — консервативная, без отката спекулятивной истории.

1. Найти ближайшее логическое время физической границы, поступления разрешённого наблюдения или завершения операции.
2. Продвинуть процессы ровно до этой границы. Связанные численные системы считать опорным методом с обязательным разрезом; одно наличие exp не разрешает большой аналитический шаг.
3. Применить относящиеся к границе эффекты и доступные наблюдения в нормативном порядке.
4. Собрать завершившиеся когнитивные задачи, проверить собственные версии оснований.
5. Дождаться их физического расчёта; незавершённые работы можно продолжать в следующем физическом кадре.
6. Только после готовности всего обязательного набора стабильно зафиксировать допустимые результаты. После этого разрешается следующая граница.

**При нехватке CPU уменьшается скорость продвижения игрового времени, а не глубина мышления и не число событий.** Визуальный клиент может показывать последний подтверждённый снимок/интерполяцию, но не менять авторитетную историю. Команды игрока привязываются к подтверждённому логическому времени, не внедряются задним числом.

Можно вычислять независимые будущие pure-задачи заранее, если сохранены снимки и версии и результат не публикуется до due. Это не разрешение читать будущие наблюдения.

## 4. Порядок фаз на одной границе

| Фаза | Выполняется |
|---|---|
| 0 | Продвижение тела/движения/текущих процессов до t по предыдущим входам |
| 1 | Физические завершения и уже назначенные эффекты, корректировка ресурсов |
| 2 | Доступные участникам наблюдения/сообщения; собственные версии повышаются только при доступном изменении |
| 3 | Проверка когнитивных завершений по версиям, установка Stale либо результата |
| 4 | Из готовых собственных результатов: оценка/эмоции, однократное обучение закрытых эпизодов, кандидаты нового намерения |
| 5 | Команды будущего интервала; проверка исполнителем; планирование новых завершений |

При одинаковом t физическое препятствие или доступный ответ уже известны перед commit мысли, завершившейся в t. Это явный выбор контракта, не «что поток успел первым».

У каждой команды `(t,phase,conflict_key,sequence)` стабилен. Для конкуренции за один ресурс `conflict_key` вычисляется от seed и номера конкуренции, а не всегда меньшего actor_id. В независимых когнитивных результатах допустим устойчивый actor_id, потому что они не распределяют ресурс между акторами. Изменение фазы требует новой версии порядка событий.

## 5. Структуры будущего движка

```cpp
struct PureWork {
    ActorId actor;
    CognitiveOpId operation;
    Ms logical_start;
    Ms logical_due;
    PersonalSnapshot immutable_input;
    RevisionVector dependencies;
    WorkResult compute() const; // без чтения World и без записи в него
};

struct PendingCommit {
    Ms logical_due;
    StableKey key;
    PureWork work;
    std::optional<WorkResult> cpu_result;
};
```

Одна активная последовательная когнитивная операция на НПС. При наличии нескольких сохранённых размышлений работают они по очереди. Скрытые неограниченные параллельные планировщики запрещены. Прогресс физического действия и когнитивной операции различаются.

```text
while simulation_requested:
    t = min(next_physical_boundary, next_observation, next_cognitive_due)
    progress_physical_until(t)
    deliver_allowed_inputs_at(t)
    batch = cognitive_completions_at(t)
    for work in batch:
        if CPU result missing: submit_or_resume(work)
    if any required CPU result missing:
        yield_wall_frame_without_advancing_logical_past(t)
        continue
    commit_batch_in_stable_order_if_own_versions_match()
    start_allowed_next_operations_with_remaining_model_budget()
```

`yield_wall_frame` не порождает новое случайное число, новое восприятие или новый эпизод. При возврате повторная доставка эффектов блокируется ID.

## 6. Почему стадийность экономит работу

Дешёвые сигналы и известные ассоциации дают предварительный список. Подробный прогноз строится только для допустимого контекста. Пока НПС выполняет знакомый шаг и нет значимого нового основания, не требуется заново строить весь проект. Pure-задачи разных НПС можно распределять по потокам и физическим кадрам.

Но это не обещает убрать стоимость всех телесных обновлений и сенсорных экспозиций. Правила обнаружения по-прежнему применяются ко всем физически подходящим объектам. Пространственный индекс даёт кандидатов без потери тех, кто входит в сенсорную область. Если их много, цена стадии действительно растёт; искусственное ограничение первыми четырьмя — приближение, не точная оптимизация.

Плановая частота обзора остаётся 30 игровых секунд. Начальные фазы обзора можно разнести seed только как **явное условие запуска нового профиля**, которое одинаково использует и эталон, и оптимизированная версия. Нельзя задним числом объявить изменение моментов мыслей «той же симуляцией быстрее».

## 7. Зависимости и инвалидирование

| Результат | Валидность зависит от | НЕ зависит напрямую от |
|---|---|---|
| Собственное ощущение | Допустимые входы тела/фокуса/предыдущей тревоги | Чужие скрытые характеристики |
| Интерпретация | Версии доступных ощущений, правила, прежних оснований | Правильное объяснение в журнале мира |
| Контекстный прогноз | Извлечённые личные факты, модель способа, свои мотивы, время | Неизвестный остаток магазина |
| Оценка проекта | Замеченный прогресс, личный прогноз, сроки, известные альтернативы | Истинная готовность стройки вне наблюдения |
| Моральная оценка | Собственные нормы, известные роли/права/аудитория | Чужой реальный приговор или мысль |
| Исполнение | Фактические ресурсы/процессы/резервы | Кэш субъективного успеха как доказательство |

Пропуск производного кэша даёт тот же логический результат и ту же модельную цену операции: CPU дешевле, мысль не быстрее. Компактная усвоенная процедура — наоборот, часть поведения; её допустимая модельная цена задаётся содержанием и применяется одинаково в обоих режимах.

При устаревании использованные операции не возвращаются. Не надо инвалидировать весь мир из-за одной новой мысли. Индекс зависимостей адресно помечает использовавшие её результаты. Изменение физического мира может инвалидировать кэш исполнителя, но не уведомляет НПС бесплатно.

## 8. Неограниченный рост нельзя скрывать удалением смысла

В эталоне списки источников и завершённых ID малы и не уплотняются. В длительном мире нужен cold storage и безопасные водяные отметки доставки, либо индексированные устойчивые ключи. Произвольное удаление старых ID уничтожает однократность; Bloom-фильтр с ложными совпадениями может удалить реальный опыт и не является точным решением.

Очередь внимания 32 и контекст 2..12 — нормативные ограничения модели. Ограничения CPU-очереди — технический backpressure: задачи при переполнении не теряются, логическое продвижение приостанавливается. Логи можно выключить; состояние, RNG и очередность событий при этом не меняются.

## 9. Что проверяет приложенный scheduler.hpp

`BarrierScheduler` выполняет простую pure-операцию над копией личного целочисленного состояния, откладывает результат до due, применяет доступные наблюдения перед commit, отбрасывает результат с устаревшей собственной версией и публикует batch целиком. Один активный job на НПС, `std::async` с ограничением числа одновременно работающих задач.

Проверены порции физической работы 1/2/17, обычный/обратный порядок получения результатов и 1/2/4 worker. Это реальное выполнение небольших C++-задач, **не** запуск многопоточного игрового мира. Copy/resume тест копирует состояние C++-объекта внутри процесса; он не доказывает файловую сериализацию будущего когнитивного save.

Результат четырех задач: начало t=0, игровая длительность 200 ms, личные результаты 1/2/3/4; все commit происходят в t=200 независимо от размера порции CPU. При новом личном наблюдении в t=100 или t=200 старый job становится Stale. Изменение личного состояния другого НПС не инвалидирует первый job.

## 10. Необходимые интеграционные измерения

Для полного мира измерять отдельно: частоту телесных границ; число экспозиций; число отобранных кандидатов; количество мыслительных операций; долю устаревших результатов; обращения памяти; стоимость прогнозов; длину CPU-очереди; время ожидания барьера; объём архивов/ID; аллокации и общее время.

Эталон и ускоренная версия должны совпасть по полному состоянию и последовательности событий, а не только числу выживших. Сравнения 1/2/4 потоков, разного размера wall-порций, 30/144 кадров и restore требуют полного интегрированного контура. Этот комплект задаёт такие требования, но не объявляет их пройденными на C++0.7.
