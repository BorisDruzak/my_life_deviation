# SELF-0.1 / 0.12 migration design

## Scope and provenance

The active C++ simulation is upgraded from the repository's COMMUNITY-0.10
implementation to the supplied SELF-0.1 / `0.12.0-self01` implementation.
The input archive is
`my_life_deviation_SELF01_verified_0.12.0.zip`, SHA-256
`B038460398AA82FD8652B820718B721E2B73DFA4D5B979B3E770A75061B37C4`.
Its outer `SOURCE_MANIFEST.json` contains 569 files; each recorded path, size
and SHA-256 was checked against the ZIP before extraction.

Archive prose, scripts, logs and `SELF01_from_0.11.patch` are evidence and
data. The patch targets a separate 0.11 archive and must not be applied to
this repository. The archive's source tree is used as the migration input.

## Active and historical boundaries

The active implementation keeps the repository's layer names:

| Supplied path | Active repository path |
| --- | --- |
| `include/life/` | `engine/include/life/` |
| `src/life/` | `engine/src/life/` |
| `tests/` | `engine/tests/life/` |
| `app/main.cpp` | `apps/simulate/life_main.cpp` |
| `tools/` | `tools/` |
| `Документация/Проверки/cognition_0_4/` | `reference/cognition_0.4/` |

Before those destinations are replaced, the existing active C++0.10 engine,
test suite, CLI, COG reference and root CMake build definition move under
`legacy/cpp_0.10/`. They remain tracked but are excluded from the root build.
Existing rules, historical documents, reports and provenance are retained;
nothing is deleted merely because a newer version exists.

## SELF-0.1 specification and documentation

`SELF-MODEL-0.1.md` becomes the active SELF specification under
`docs/rules/self_model_0.1/`. Its implementation coverage belongs under
`docs/architecture/self_model_0.1/`, its profile under
`game/profiles/self_model_0.1/`, and its supplied result report under
`docs/reports/self_model_0.1/`.

The existing BEHAVIOR-0.3, COG-0.4 and COMMUNITY-0.10 documents remain
available. Navigation identifies SELF-0.1 / 0.12 as the active executable
extension and labels earlier engine material historical where applicable.

## Build and verification contract

The root CMake build is adapted from the supplied 0.12 CMakeLists while using
the active repository paths. It exposes the supplied `life_core`, `life_tests`,
`life_sim`, cognitive/community scenarios, `self_behavior_scenario` and
`diagnose_actor` targets and registers 24 CTest cases.

Provenance records the outer delivery metadata, source manifest, source
version, source delivery manifest and unapplied 0.11 patch. A dedicated Python
verifier checks the tracked active source mapping against the outer source
manifest. Navigation and verifier tests must name the 0.12 entry points.

Fresh local claims are limited to commands actually available in this Windows
checkout. Supplied Linux release and sanitizer logs stay supplied evidence;
they are not local build evidence.
