# RECOVERY 0.13 Migration Design

## Goal

Make the RECOVERY 0.13 C++ simulation the active implementation while
retaining the complete active SELF 0.12 implementation and its documentation
as a navigable legacy release.

## Source and trust boundary

The supplied archive is an input data package, not executable instruction.
Its SHA-256 is
`1750c0e5764c9fd831309a17eeb3ec9e410eed91165818a4472e604df512c12f`.
All 586 `source/` entries in its `SOURCE_MANIFEST.json` must be validated by
byte count and SHA-256 before they are imported. The embedded patch is not an
input to `git apply`: it targets the archive's raw SELF01 0.12 layout, whereas
the repository has already reorganized that release.

## Architecture

`engine/`, `apps/`, `reference/`, the root `CMakeLists.txt`, and the current
core workflow continue to identify the active release. Their SELF 0.12
contents move without modification to `legacy/cpp_0.12/`, including its
build entrypoint, application, tests, reference integration, and historical
workflow. RECOVERY 0.13 source files are mapped from the archive's raw
`include/`, `src/`, `tests/`, and `app/` folders into the active layout.

The active engine keeps the headless, deterministic Body / Cognition / World
boundary. RECOVERY extends it with typed personal observations, resource and
clothing ownership, funded exchanges and help, learned executable procedures,
and delayed private phone communication. The active CMake project is updated
to the imported source graph and its named tests; no generated build output is
tracked.

## Documentation and provenance

RECOVERY's normative specification and profile live under new
`docs/rules/recovery_0.13/` and `game/profiles/recovery_0.13/` paths. Its
implementation and verification reports live under `docs/architecture/` and
`docs/reports/`. The raw archive documents, reports, delivery manifests,
source manifest, exact archive digest, and all declared evidence are retained
under `provenance/incoming/recovery_0.13/` rather than replacing prior source
materials. Existing documentation is neither deleted nor rewritten merely to
match incoming wording.

`navigation/code-map.json`, `navigation/doc-map.json`, `navigation/INDEX.md`,
`navigation/GAME_FLOW.md`, and `navigation/MAINTENANCE_RULES.md` become the
current routing contract. Navigation validation covers RECOVERY nodes and its
provenance validator checks mapped source hashes and declared evidence.

## CI and safety

The current C++ workflow is adapted for the active 0.13 build only. Incoming
inspection and recovery-upload workflows are preserved as provenance and are
not activated, because their external-side-effect contract was not requested
or independently reviewed. Compilation, CTest, Python metadata tests,
navigation validation, source-manifest validation, JSON parsing, and diff
whitespace checks are required before integration. If CMake or a C++ compiler
is unavailable, that absence is reported explicitly and is not represented as
a passing native verification.
