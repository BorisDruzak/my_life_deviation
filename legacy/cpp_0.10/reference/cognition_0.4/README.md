# Исполняемые контракты COG-0.4

Это самостоятельный C++20-эталон к алгоритмической спецификации, **не новая версия движка мира**. Никаких LLM и сторонних C++-библиотек. `scheduler.hpp` использует обычные потоки стандартной библиотеки на небольших pure-задачах.

Из корня комплекта/репозитория:

```sh
cmake -S "Документация/Проверки/cognition_0_4" -B build-cognition -DCMAKE_BUILD_TYPE=Release
cmake --build build-cognition --config Release -j2
ctest --test-dir build-cognition -C Release --output-on-failure --no-tests=error
./build-cognition/examples
```

Для санитайзеров с GCC/Clang: отдельный build с `-DCOG_SANITIZE=ON -DCMAKE_BUILD_TYPE=Debug`. Windows/MSVC не проверялись; конкретный путь executable зависит от генератора CMake.

`profile.json` загружается **CMake на этапе конфигурации**, генерирует `profile.hpp` и задаёт новые коэффициенты fusion, гистерезиса категорий, примера функции неудобства и дисконтирования. После изменения нужна повторная конфигурация и сборка; численные фикстуры тестов относятся к `cog-0.4-test-1`. Старые нормативные коэффициенты сохранены непосредственно в формулах эталона. Это не JSON-loader работающего движка.

| Файл | Ответственность |
|---|---|
| core.hpp | Валидация, время, знаковая шкала, статус посылок |
| subjective.hpp | Сигнал/ощущение, частные интерпретации, fusion, категории, однократность |
| attention.hpp | Приоритет, удержание/перестройка, работа во времени, эталонный top-K |
| valuation.hpp | Мораль, стыд/вина, санкции, реестр эффектов, отложенная ценность |
| scheduler.hpp | Логический барьер, pure-job, версии, физические порции и worker |
| contract_tests.cpp | 69 именованных проверок; исключения, не assert, поэтому работают в Release |
| examples.cpp | Численные примеры основной спецификации |

Пример не интегрирует долговременную память, полноценный SEM, мир 0.7 или динамику общества. Запрещено выдавать его число тестов за число реализованных механик игры.
