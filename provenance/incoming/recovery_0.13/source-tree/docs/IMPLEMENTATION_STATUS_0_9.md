# C++ 0.9.0 — что действительно проверено

Основа: предоставленный архив C++0.8.0, локальный import 6beea12. Старые матрицы и спецификации
сохранены. Новый код не опубликован в GitHub в этом обращении. Patch применяется к архиву0.8.

| Механизм | Статус 0.9 |
|---|---|
| Тело, еда, вода, сон, прежние COG-операции | Сохранены; прежние тесты повторно запущены |
| Вложенная социальная операция в Talk | Интегрирована, отдельное предложение/ответ/длительность/отмена |
| Знание «способ приятен» | Отдельный prior/mastery/source; не телесный результат |
| Истинная переживаемая приятность | Отдельный собственный отклик; не передаётся прогнозу как правильный ответ |
| Личные предпочтения/нормы | Семь узких условий в компилируемом каталоге, без универсального запрета по полу |
| Публичность | Только замеченные лица/личные ожидания, не общий вердикт толпы |
| Статус | Ожидаемое одобрение, память обратной связи, собственная значимость; не полная иерархия |
| Стыд/вина | Существующие эмоции получают доступные интерпретированные основания, в том числе неодобрение |
| Контекстная память взаимодействий | Способ × человек × предмет × публичность; не всю жизнь сравниваем со всей |
| Предметная память | Собственник/держатель/источник/статус/сообщения/полезность, поддержка противоречий |
| Заём/возврат | Реальные передачи и сохраняемый Loan, без торга и автономного взыскания |
| Чтение | Фактическое действие и обучение содержанию; опыт физконтакта из текста не создаётся |
| Новая социальная цель | Нужный предмет позволяет спрашивать независимо от голода/социального дефицита |
| Причинное обучение C | По-прежнему не подключено как самостоятельные вопросы в общем цикле |
| Ошибки узнавания/полный SEM | Не реализованы |
| История происхождения новых норм | В этом стенде seed/фикстуры задают начальные priors; не полностью прожитая биография |
| Давление и повтор | Адресная история и конечная цена; родительский Talk сохраняет старые упрощения retry |
| Планы | Есть заданная библиотекой схема «сведения→заём→изучение→возврат», не произвольный генератор планов |
| Репутация | Узкая безопасность контакта/исполнение займа, локальные утверждения; автономных слухов нет |
| Сохранение | Новое состояние 0.9, проверки до ответа и во время согласованного контакта |
| Оптимизация | Собственные снимки, индексы, активные ID, общий бюджет; сравнение с reference/worker/logging |
| Долговременная память | Append-only, cold storage не решено |

Особенно важно: `ClaimItem` означает высказывание «эта вещь моя». Оно может быть правдивым.
Шесть таких высказываний в общем суточном мире не означают шесть обманов. Проверяется
фактическая принадлежность в отдельной диагностике; НПС не получает этот правильный ярлык.

Контролируемые сцены ставят разговор и исходные знания/цели, но НЕ расписание последующих
социальных поступков. `mixed` задаёт только стартовую обстановку и позволяет беседам возникать
самостоятельно. Никакая квота объятий/нарушений в коде не задаётся.

Высокая частота контактов, отсутствие вложенных отказов в mixed-day и ожидающий возврат
в borrow-novice — наблюдаемые ограничения баланса/каталога, не объявленные успехи реализма.

Прогноз вероятности согласия и прогноз успешности физического исполнения ещё не являются
двумя полными обучаемыми моделями: отмена Unavailable сохраняется, но универсального
объяснения/перестройки способов после такой неудачи нет. В общем seed базовые веса норм
одинаковы; индивидуальные различия норм для проверок задаются фикстурами, а не полной
культурно-биографической генерацией.
